## 페이지 / 라우팅 확인 결과

- 라우터는 기존 `HashRouter`를 유지한다.
- GitHub Pages 새로고침 404 위험을 낮추기 위해 BrowserRouter로 변경하지 않았다.
- 예상 배포 URL: `https://slowlyp.github.io/loo-ting-lab/`
- Resume PDF 예상 배포 URL: `https://slowlyp.github.io/loo-ting-lab/assets/resume/documents/resume.pdf`
- 로컬 개발 환경에서는 `import.meta.env.BASE_URL`이 `/`로 동작해 `/assets/resume/documents/resume.pdf`로 접근 가능하다.

## GitHub Actions workflow 구성

- main 브랜치 push 시 배포
- `workflow_dispatch` 수동 실행 지원
- `npm ci`
- `npm run lint`
- `npm run build`
- `dist` 폴더를 GitHub Pages artifact로 업로드
- GitHub Pages로 deploy

## GitHub Settings에서 직접 해야 할 설정

Repository Settings
→ Pages
→ Build and deployment
→ Source
→ GitHub Actions

## 개인정보 주의

- `public/assets/resume/documents/resume.pdf`는 배포 후 공개 URL로 접근 가능하다.
- 공개 전 주민등록번호, 생년월일, 주소, 전화번호, 상세 학번 등 민감한 개인정보 포함 여부를 반드시 확인해야 한다.

## 남은 문제

- 실제 GitHub Pages 배포는 main 브랜치에 병합 및 push 후 GitHub Actions 실행 결과로 확인해야 한다.

## dev에 병합해도 안전한지 여부

- lint와 build가 통과했으며 배포 설정 및 문서 중심 변경이므로 dev 병합 가능 상태로 판단한다.
