## Goal

Keep the bright Work Gallery as the default while adding an explicit, persistent navy/slate dark mode. Improve the network canvas so points, lines, and triangle fills remain subtle but easier to see in both themes.

## Theme requirements

- Theme type: `light | dark`.
- Default and invalid-value fallback: `light`.
- Storage key: `loo-ting-lab-theme`.
- Apply `data-theme` and `style.colorScheme` to `document.documentElement`.
- Keep theme state independent from `loo-ting-lab-language`.
- Add a localized, accessible ThemeToggle beside the KO/EN control.

## Visual scope

- Header, Footer, App shell, Work, grouped project cards, previews, badges, About, Project Detail, Resume, and Contact direct routes.
- Dark surfaces use deep navy/slate rather than black.
- Real preview images retain their visibility; only surrounding surfaces and overlays change.

## Network tuning

- Light radii: 1.65 / 2.15px; point opacity 0.25 / 0.30; line max 0.17; triangles 0.032 / 0.038.
- Dark radii: 1.75 / 2.25px; point opacity 0.30 / 0.36; line max 0.20; triangles 0.038 / 0.046.
- Line width: 0.75px.
- Preserve point counts, connection distance, pointer radius, mobile frame limit, DPR cap, reduced motion, requestAnimationFrame, pointer-events, and cleanup.

## Protected scope

- No new dependencies.
- Do not change package manifests, Vite/GitHub Pages/workflows, Resume data/PDF/links, project facts, preview/live-site/ownership structures, or project translation body copy.

## Completion criteria

- Theme toggle, persistence, refresh restoration, invalid-value fallback, and language independence work.
- Primary screens remain readable in both themes.
- Canvas switches palette immediately with the theme.
- `npm.cmd run lint`, `npm.cmd run build`, and `git diff --check` pass.
